# Предпросмотр состава опроса

## Понимание задачи

- Администратору нужен текстовый просмотр того, какие кандидаты попадут в будущий опрос с учётом force и exclude.
- Предпросмотр не должен публиковать Telegram poll, менять состояние сессии или снимать турниры с force-очереди.
- Отбор не должен расходиться с `/poll`.

## Допущения

- Команда называется `/preview`, доступна только авторизованному администратору в личном чате.
- Она принимает те же строгие формы аргументов, что `/poll`, чтобы проверить конкретную дату и single-choice режим до публикации.
- Результат — снимок текущих данных API и БД; будущий `/poll` может отличаться после внешних или административных изменений.

## Дизайн

`PollCandidatePreparationService` централизует неизменяемую подготовку кандидатов: рассчитывает дату и stop time, одновременно читает exclude, force и API, применяет текущие фильтры, ставит подходящие force-кандидаты первыми и ограничивает список девятью позициями. Он возвращает структурированные исходы для просроченной даты, более девяти force-кандидатов и пустого списка.

`StartPollService` использует этот результат перед публикацией и сохраняет прежние уведомления/удаление force после успешного poll. `PreviewPollService` использует ту же подготовку, форматирует те же HTML-страницы без видимой строки ID и со всеми выбранными категориями стоимости, но не зависит от publisher или repository записи. Так совпадают состав, порядок и ограничения на одном снимке без дублирования алгоритма.

Worker разбирает `/preview` существующим `StartPollRequestParser`, отправляет короткий заголовок и страницы кандидатов, а для ожидаемых отказов пишет нейтральное личное сообщение. Ошибки API и курсов скрываются от пользователя за общим сообщением, а в логе остаются только контекст чата/пользователя и счётчики.

## Безопасность и ошибки

Авторизация и private-chat проверяются до разбора аргументов и внешних вызовов. В логах не сохраняется полный payload команды, URL запросов или ответы API. Предпросмотр не имеет write-зависимостей для публикации, сессий или force-очереди.

## Тестирование

Тесты preview use case проверяют force-first порядок даже для турнира вне обычных фильтров, исключение заранее заблокированного турнира, отсутствие видимого ID, полный список цен и отсутствие удаления из force-очереди. Отдельно проверяются 10+ force-кандидатов и отклонение даты до запроса API. Регрессионные тесты `/poll` подтверждают сохранение поведения после извлечения общего сервиса. Полный набор тестов, форматирование и аудит NuGet входят в done-критерий.

## Журнал решений

| Решение | Альтернативы | Причина |
| --- | --- | --- |
| Общий preparation service | Дублировать код или dry-run публикации | Сохраняет точное совпадение отбора без побочных эффектов. |
| Те же аргументы, что `/poll` | Только следующий субботний опрос | Позволяет проверить любой поддерживаемый сценарий до запуска. |
| Личный чат | Рабочий чат | Не раскрывает служебный состав force/exclude участникам рабочего чата. |
| Снимок без гарантий будущего | Резервировать кандидатов | Не вводит лишнее состояние и не меняет естественный процесс обновления данных. |
