# Оптимизация пагинации API CHGK

## Понимание задачи

- Нужно уменьшить количество запросов к API CHGK без изменения данных, порядка и свежести выборки.
- Вызовы уже ограничены двумя отправками в секунду, поэтому оптимизация должна уменьшать именно количество dispatches, а не параллелизировать их.

## Исследование

Клиент получает турниры на дату через `/tournaments` с `itemsPerPage=100` и следует ссылке следующей страницы. Официальный OpenAPI CHGK документирует максимальное значение `itemsPerPage` как `512`. Поэтому выборка из `N` элементов требует `ceil(N/512)` запросов вместо `ceil(N/100)` и возвращает ту же коллекцию; при `N ≤ 100` количество запросов не меняется.

Документация не задаёт безопасного фильтра `/tournaments` для массового поиска по ID, поэтому последовательные запросы `GetTournamentsByIdsAsync` не заменяются недокументированным query-параметром. `/force` и `/makepost` уже передают дедуплицированные IDs. Параллелизация не уменьшит число запросов при rate limit, а краткоживущий кэш изменит требование получать свежие данные перед критическими сценариями — оба варианта исключены.

## Дизайн

`ChgkTournamentClient` хранит page size константой Infrastructure-слоя и строит первый date-query с `itemsPerPage=512`. Безопасная обработка `view.next`, mapping JSON-LD, retry и process-wide pacer остаются без изменений; следующие страницы всё равно проходят существующий HTTP rate limiter.

## Тестирование

Инфраструктурный тест сохраняет проверку JSON-LD и перехода на следующую страницу, а также фиксирует `itemsPerPage=512` в URI первого запроса. Полный набор тестов, форматирование и аудит NuGet входят в done-критерий.

## Журнал решений

| Решение | Альтернативы | Причина |
| --- | --- | --- |
| `itemsPerPage=512` | Текущие 100 | Документированный максимум уменьшает число запросов без изменения ответа. |
| Не добавлять batch ID filter | Недокументированный `id[]` | Нельзя гарантировать корректность и совместимость API. |
| Не кэшировать | Краткоживущий memory cache | Сохраняет свежесть данных и точность `/poll`/`/preview`. |
