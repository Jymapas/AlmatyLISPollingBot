# Скрытие ID из сообщений перед опросом

## Понимание задачи

- Сообщение со списком кандидатов, публикуемое перед Telegram poll, не должно показывать `tournament id`.
- ID должен оставаться доступным только в результате команды `/options`.
- `/excluded` использует тот же список турниров, но не является `/options`, поэтому тоже не должен выводить ID.

## Дизайн

`TournamentListFormatter` получает обязательный `TournamentIdDisplayMode` без значения по умолчанию. Это делает намерение каждого вызывающего use case явным: `StartPollService` и `/excluded` выбирают `WithoutTournamentId`, а только `ListTournamentOptionsService.ExecuteAsync` выбирает `WithTournamentId`.

Ссылка в заголовке турнира остаётся неизменной: ID присутствует в URL как техническая часть ссылки, но отдельная видимая строка `ID: …` отсутствует. Выбор кандидатов, сортировка, цены, пагинация, Telegram poll и API-запросы не меняются.

## Безопасность и ошибки

Режим валидируется в formatter, поэтому неизвестное значение не даёт случайно сформировать сообщение. Изменение влияет только на отображение уже полученных данных и не изменяет авторизацию команд, Telegram transport или постоянное состояние.

## Тестирование

Unit-тесты formatter проверяют оба режима и сохранение ссылки. Тест запуска опроса проверяет отсутствие видимой строки ID в опубликованном HTML, а тесты list use case фиксируют наличие ID в `/options` и отсутствие в `/excluded`. Полный набор тестов, форматирование и аудит NuGet входят в done-критерий.

## Журнал решений

| Решение | Альтернативы | Причина |
| --- | --- | --- |
| Явный enum-режим | Неявный default или второй formatter | Не позволяет новому use case случайно раскрыть ID. |
| Не менять URL ссылки | Убирать и ссылку | Ссылка остаётся полезной навигацией без отдельного показа идентификатора. |
| Скрыть ID также в `/excluded` | Сохранять там ID | Формулировка «только для `/options`» применяется буквально. |
