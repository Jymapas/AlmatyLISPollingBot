# Аргументы команды `/poll`

## Понимание задачи

- Администратор должен запускать опрос не только на ближайшую субботу, но и на явно указанную дату.
- Команда `/poll 1` должна создавать опрос для выбора одного турнира.
- Базовая команда `/poll` сохраняет текущую дату ближайшей субботы, два победителя и multiple-choice режим.
- Указанная дата не меняет слоты `13:00` и `15:30` UTC+5, фильтры кандидатов, exclude/force или лимит вариантов.
- Опрос не должен публиковаться, если его рассчитанное время автоматической остановки уже прошло.
- Число выбираемых турниров должно сохраниться в `PollSession` для будущего подсчёта результатов.

## Допущения

- Дата означает дату проведения турниров.
- Поддерживается строгий формат `dd.MM.yyyy`.
- Число `1` включает Telegram single-choice; расширенные режимы числа победителей не добавляются.
- Автоостановка остаётся за один календарный день до целевой даты в `DefaultPollStopTime`.

## Варианты

1. **Рекомендованный:** строгие четыре формы команды: `/poll`, `/poll 1`, `/poll 25.07.2026`, `/poll 25.07.2026 1`; отдельный parser создаёт request Application-слоя.
2. Принимать произвольные DateTime-форматы и порядок аргументов. Это неоднозначно для русскоязычного интерфейса и сложнее документируется.
3. Ограничиться заменой текста вопроса без хранения числа победителей. Будущий подсчёт не сможет восстановить top-1 или top-2 для исторического опроса.

Выбран первый вариант.

## Дизайн

`StartPollRequestParser` разбирает payload после `/poll` и возвращает только допустимые формы. Роутер проверяет права, до вызова use case отклоняет неверный синтаксис нейтральной подсказкой и передаёт request в Application.

`StartPollService` использует request с явной датой либо существующий расчёт ближайшей субботы. После загрузки настроек он рассчитывает `stopAtUtc` и возвращает ожидаемый отказ до обращения к CHGK API и Telegram, если это время уже наступило. Для количества `1` вопрос говорит «Выбираем 1 синхрон», Telegram получает `AllowsMultipleAnswers = false`, а для количества `2` сохраняется текущее поведение.

`PollSession.DesiredTournamentCount` сохраняется с default `2`; миграция оставляет все исторические сессии в стандартном top-2 режиме. Текущий `StopPollService` по-прежнему только закрывает опрос: дальнейший подсчёт результатов появится позже и сможет прочитать это значение.

## Безопасность и ошибки

Парсер ограничивает формат и число входных токенов, не допускает неявных дат и лишних аргументов. Роутер авторизует команду до обработки аргументов. Даты с прошедшей автоостановкой не вызывают внешних запросов. В логах фиксируются только дата и число выбираемых турниров, без полного пользовательского ввода, токенов или тел API.

## Тестирование

Unit-тесты parser покрывают все допустимые формы, некорректный порядок и формат. Тесты use case проверяют явную дату, stop time, single-choice и сохранённое число победителей; обычный запуск остаётся top-2/multiple-choice. Полный набор тестов, форматирование и аудит NuGet входят в done-критерий.

## Журнал решений

| Решение | Альтернативы | Причина |
| --- | --- | --- |
| Формат даты `dd.MM.yyyy` | ISO, свободный парсинг | Предсказуемый формат для русскоязычной команды. |
| Только суффикс `1` | Произвольное число победителей | Точно соответствует запросу без нового режима конфигурации. |
| Telegram single-choice для `1` | Multiple-choice с top-1 | Формулировка «выбора только одного» выполняется и для голоса пользователя. |
| Хранить desired count | Только менять заголовок | Будущий подсчёт результатов остаётся корректным для исторических опросов. |
