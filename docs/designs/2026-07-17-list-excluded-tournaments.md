# Просмотр исключённых турниров

## Понимание задачи

- Администраторам нужна отдельная команда, которая показывает заблокированные турниры для ближайшего опроса.
- Команда предназначена только для личной переписки с ботом, как и `/exclude` и `/options`.
- В списке нужны только турниры, которые подходят для ближайшей целевой субботы и поэтому могли бы попасть в опрос без исключения.
- Для определения даты, фильтрации, сортировки и представления используются те же правила, что и у `/options`.
- Неактуальные исключения и записи, не проходящие обычные фильтры кандидатов, не выводятся.
- Фича не изменяет список исключений и не затрагивает очередь `/force`.

## Допущения

- «Ближайший период» означает ближайшую субботу в часовом поясе из настроек бота, как в `/poll` и `/options`.
- Команда называется `/excluded`.
- Согласование дизайна следует из явно заданной пользователем очереди реализации; дополнительных продуктовых вопросов нет.

## Варианты

1. **Рекомендованный:** расширить `ListTournamentOptionsService` отдельным сценарием и повторно использовать выбор кандидатов и существующий HTML-форматтер. Это сохраняет единые правила и не дублирует бизнес-логику.
2. Запрашивать каждое исключение из API по ID. Это выводило бы исключённые турниры вне целевой даты и создавало бы N внешних запросов.
3. Хранить снимок турнира при исключении. Это потребовало бы миграции и могло бы показывать устаревшие данные.

Выбран первый вариант.

## Дизайн

`ListTournamentOptionsService.ExecuteExcludedAsync` получает настройки и рассчитывает ближайшую субботу, одновременно запрашивает исключённые ID и список турниров на эту дату. Затем он использует `PollCandidateSelectionService.SelectAllCandidates` и оставляет только кандидатов с `IsExcluded`. Форматирование остаётся в `TournamentListFormatter`, поэтому список содержит ссылку, ID и маркер исключения, а его страницы не превышают лимит Telegram.

`TelegramUpdateRouter` распознаёт `/excluded`, проверяет личный чат и существующую авторизацию до вызова use case. Если подходящих исключённых турниров нет, пользователь получает нейтральное сообщение с датой. Транспортный слой не содержит правил выбора турниров.

## Безопасность и ошибки

Команда не принимает произвольных аргументов и не создаёт новых внешних интеграций. Существующая авторизация выполняется до доступа к данным. В логах сохраняются только идентификатор пользователя, чат и число найденных турниров; секреты и ответы API не логируются. Сбои CHGK API не должны раскрываться пользователю в тексте сообщения.

## Тестирование

Unit-тесты use case проверяют: выбор только актуальных исключённых кандидатов, применение обычных фильтров, стабильную дату и пустой результат. Полный набор `dotnet test` проверяет совместимость с маршрутизацией и существующими слоями.

## Журнал решений

| Решение | Альтернативы | Причина |
| --- | --- | --- |
| Использовать `/excluded` | `/blocked`, аргумент `/exclude list` | Команда краткая, не конфликтует с добавлением исключений и не перегружает `/exclude`. |
| Показывать только ближайшую субботу | Все сохранённые ID, произвольный диапазон | Соответствует существующей модели даты и не требует новых параметров. |
| Расширить существующий use case `/options` | Новый клиент API, сохранённый снимок | Гарантирует одинаковые фильтры, сортировку и формат вывода. |
